# Portable reference

Paths in backticks are relative to the package root unless explicitly described as output examples. Read only modules whose triggers apply. Provenance and excluded private inputs: `PROVENANCE.md` and `docs/research/conditional-inputs.md`.

## Report and evidence boundaries

Keep the reader-facing report consolidated and separate from reproducibility artifacts. Do not append a new overriding annex to an obsolete process; rewrite or version the product cleanly.

### Migrate or retire a runtime authority

Separate an operational binding repair from a change to the economic mandate. Preserve the accepted investment method unless the user explicitly reopens it; require the blind method-comparison protocol below for substantive method changes, not merely for replacing a stale scheduler copy with the already accepted authority.

1. Read the actual live job and trace its prompt through the working order to the economic mandate. Compare exact paths and checksums; inspect enabled jobs for obsolete runtime bindings, because a correct repository file does not update an embedded scheduler copy. Distinguish historical mentions from executable bindings.
2. Save the affected job, pause only that job through its owning scheduler command, and read back its disabled state before cutover. Preserve schedule, model/provider, skills, workdir, delivery and permissions. Never restore the entire shared scheduler file over concurrent updates.
3. Replace embedded working-order copies with a short package-relative reference to the canonical working order, keeping the economic mandate separately checksum-bound. Archive obsolete mandate bytes unchanged, then replace a retired external entrypoint with a non-executable retirement notice rather than a redirect or another live copy. Verify that the archive retains the historical checksum and the former entrypoint no longer satisfies it; never relabel old reports as new-version output. Inspect the entire retirement notice, not just its marker and checksum: a non-executable notice can still falsely designate an obsolete mandate as current. Remove its own current-version/hash declaration and point neutrally to the canonical runtime runbook, keeping historical archive provenance explicit.
4. Read back the exact live job and perform a read-only cold-load probe from its actual prompt through both referenced files. Check path/hash and a few content-specific control questions. Compare product state through read-only SQLite before and after; do not create Candidate decisions, trades or mail merely to test mandate resolution. State that this proves binding resolution, not a scheduler full run or analysis quality.
5. Obtain independent review of the exact changed files and live binding, then resume the same job on its preserved schedule without a forced run. Read back enabled state, next run, prompt and unchanged configuration; a reviewed but paused job is not a completed migration.
6. Commit the scoped repository authority/binding changes, push and verify the exact remote commit and deployed file contents. Verify host-only scheduler and retirement state separately rather than claiming they are Git-tracked. Disclose a repair branch that is not merged; do not publish unrelated existing commits merely to obtain a push.

Require an evidence bundle for load-bearing empirical claims: case ledger, inputs, code, configurations, outputs, adjustment ledger, and a manifest that binds the complete input→code→output path.

### Reconstruct the authority corpus before revising the model

Before asking a council to revise the stockpicking framework or merging a new thesis into it:

1. Read the current consolidated research report from its direct source; do not infer its contents from implementation docs.
2. Read the operative product, screening, and evaluation contracts plus the current review procedure. These define what the running product actually promises.
3. Locate the frozen empirical package and prior council verdicts that created the current evidence boundary. Treat legacy datasets and superseded reports as historical evidence, not operative authority.
4. Search plans and session provenance only to recover references and decisions missing from the canonical files. If a referenced temporary artifact no longer exists, record the provenance gap instead of reconstructing an authoritative verdict from memory.
5. Classify every candidate document as one of: `current research authority`, `operative contract`, `historical evidence`, `new conceptual input`, or `provenance only`. Present this short map before convening reviewers.
6. Give the council the roles of the documents and the exact question to resolve. Require it to state which existing rule is preserved, refined, or rejected; a newer macro narrative does not silently supersede the frozen stockpicking process.

When a new conceptual report adds a useful lens, first express it through existing review fields and testable disputes. Add a new gate or score only if separate evidence shows that the lens has incremental decision value; conceptual elegance alone is not validation.

Test a proposed lens with a preregistered blind shadow comparison before altering the product: freeze the candidate set, cutoff and one fact-only source packet per case; give the normal reviewer and the lens reviewer the same packet under mutually exclusive mandates; freeze both outputs before comparison; and count only a changed load-bearing valuation assumption, observable falsifier or hypothetical disposition as material. A new question or additional prose is process improvement, not incremental decision information. See `docs/research/stockpicking/references/incremental-lens-testing.md` for the full protocol.

When re-running completed deep dives under a revised format, isolate the format effect explicitly:

1. Preserve each baseline byte-for-byte and freeze the original cutoff, reference price and domain context.
2. Derive a verdict-free fact packet that excludes the old status, ranking, recommendation and missing condition; scan it mechanically for leaked decision labels before review.
3. Give each blind reviewer only one company's packet and the new mandate; prohibit later research and productive state mutation.
4. Compare old and new on the owned economic claim, load-bearing valuation assumption, primary falsifier, missing condition, final status and relative preference.
5. Classify an unchanged status with a materially changed primary falsifier or promotion condition as a thesis change, not “same result.” Classify clearer causal structure or better monitoring with the same decision variables as a better model only.
6. Keep any changed research condition out of live candidate state until the owner explicitly authorizes adoption; a re-review is evidence, not a status write.

When a report is already mature, inspect the latest decisions and real artifacts before proposing changes. Fix contradictions and evidence gaps without redesigning the product from a single error. When the owner asks whether a deep dive covered every direction, read its actual report and audit trace, then state separately the completed economic scope, unresolved disclosure limits, and peer comparisons not performed. Restrict a strongest-candidate claim to the securities actually reviewed; one full competitor comparison plus operating headlines about other peers does not establish sector-wide investment superiority.

When changing economic instructions, design approval is not production proof. The canonical Deep-Dive prompt contains the complete binding economic policy; this skill and its references supply routing and specialist detail, not a competing policy. For the owner's explicitly accepted asymmetry mandate, preserve original inputs and exercise fresh company outputs through the updated complete mandate after integrated review; do not demand a new blind A/B merely to re-authorize the already decided purpose. Do not claim incremental selection performance from clearer forecasts or arithmetic checks. A separately proposed new lens or selection rule still uses the preregistered protocol above before any claimed empirical improvement.

Before ranking independently modeled cases by scenario returns, align horizon, distribution timing, share-count treatment, cash normalization and terminal multiple. Recalculate comparable no-rerating paths where possible; otherwise disclose the incompatible conventions and do not rank on decimal return differences, because end-wealth CAGR and cash-distribution IRR can encode different economics. Treat executed verification scripts as arithmetic/artifact checks, not independent validation of future assumptions; separately spot-check the primary-source operands that carry the judgment.

For structured handoffs covering several securities, require one complete parseable payload per security; a shared pair/group summary, YAML block, or prose is not a substitute. Validate the exact field set mechanically across the full batch before adoption. Define `evidence_as_of` as the information cutoff; if the first executable valuation close is later, date it inside `valuation` rather than moving the evidence cutoff forward.
