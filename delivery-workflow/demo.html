A small document tool, step by step

Illustrative only. This is not a historical case, execution log or claim of a successful run. This page runs no commands, calls no service and saves nothing.

Private task → audit → actual work + record → status → check + handover

1. Agree on the result

The user asks for a local tool that summarizes headings from text files. The agent reads sample inputs, establishes encoding and output rules, and creates or reuses a design. Unresolved material choices go to the user. The private task names scope, deliverables and observable checks.

2. Audit and build

Audit returns an assignment, not finished software. The agent performs included phases in catalog order and records observed evidence after each one. A proven approach or adequate existing plan may justify an evidenced exclusion; mandatory phases cannot be excluded. A failed experiment is recorded honestly and can stop the run.

3. Verify the actual artifact

Tests cover agreed valid and invalid input. A direct check executes the actual tool on an authorized sample and saves its real output. Replaced entry points are checked for accidental re-entry. If independent review is required, a separate reviewer examines the exact candidate; the implementation agent cannot substitute its own approval.

4. Resume and deliver

After interruption, status returns the next assignment. The agent rereads task, evidence and current project state. Changed scope requires a new audit, not edited approval. Postmortem records use instructions, actual checks, limits and cleanup. Check validates the saved evidence; the final response distinguishes working files, commits and publication.

Blocked variant

If the permitted private folder lies below a Git repository, configure refuses it. The agent reports the blocker and asks for a compliant authorized location. It does not disable the guard, relocate the repository metadata or invent subsequent receipts.
